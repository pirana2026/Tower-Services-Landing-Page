Drone

Turn drone imagery into individual tree crowns and species maps.

Try Drone Application ↗

🔒 Google sign-in required for access.

About this service

Upload one stitched drone photo of your site (a GeoTIFF orthomosaic) and Drone outlines every tree crown it can see. Look-alike crowns are grouped together, you name each group once, and every tree in that group gets the species you typed.

Every run is saved on its own, so you can change the settings and try again whenever you like. Download a species map for Google Earth or any GIS tool, CSV tables with every crown and its species, and a STAC record.

Documentation ↗ GitHub Repository ↗

How to use it

1
Create a project: Sign in with Google, then start a new project for your site.
2
Upload orthomosaics: Add a GeoTIFF (.tif or .tiff) with its coordinates built in, from your computer or a Google Drive link shared as "Anyone with the link". A ground resolution finer than 8 cm per pixel works best, and a project takes up to 10 orthomosaics and 5 GB. If the file has no coordinates, the app asks for the EPSG code.
3
Detect and group: Pick a detector model and settings, then run the analysis. Drone outlines the crowns and groups look-alike ones. The elbow, silhouette and Davies-Bouldin charts suggest how many groups to use, and the t-SNE crown map shows how clean those groups are.
4
Check and tune: Compare the red outlines on the detection overlay with the trees you can see. If results look poor, open the Guide tab, change the suggested setting and run again.
5
Name and export: Type a species for each group, then export the species map (KMZ), CSV tables and STAC record. Every run gets its own read-only folder in FileBrowser.

Methodology

How Drone works

From drone orthomosaic to tree species map · Detectree2 crown detection · DINOv2 embeddings · KMeans grouping · user labelling

1UploadOne stitched GeoTIFF of your site
2DetectDetectree2 outlines every crown
3GroupDINOv2 + KMeans cluster look-alikes
4NameYou type one species per group
5ExportMap, CSV, GeoJSON, STAC item

System architecture

  • The backend owns state, the worker computes, and the orchestrator only schedules.
  • You sign in with Google in the browser. The web frontend is a page served by Nginx and talks to the FastAPI backend over REST.
  • The backend owns project and run state and sends the run to a GPU worker, which runs Detectree2 and DINOv2, one process per run.
  • Airflow + STACD schedule the runs and call back into the backend when they finish.
  • Storage holds the database for state and one folder per run: orthomosaic, crown polygons, crown crops, clusters, exports and the STAC item.
  • FileBrowser gives a read-only share link to a run's folder, so you can view and download the generated files.

The pipeline: eight steps, one needs you

Stage 1 · Find the crowns (automatic)

StepWhat happens
1 · OrthomosaicGeoTIFF from a drone survey, ideally finer than 8 cm/px.
2 · Rescale and tileBrought to the GSD best suited for the model, then cut into overlapping tiles.
3 · Detectree2Mask R-CNN outlines the crowns in each tile, with a confidence score for each crown.
4 · Crown layerTiles are stitched; weak, tiny, huge and duplicate crowns are removed.

Stage 2 · Group and name (automatic, then labelling)

StepWhat happens
5 · Crown cropsEach polygon is cut from the full-resolution image.
6 · DINOv2 + PCAOne embedding per crown, reduced to 50 dimensions.
7 · KMeansCrowns are grouped for every k; three scores suggest a k.
8 · User labelsAfter reviewing the crowns, you name each group and every tree crown in that group gets labelled.

Exports: species map (KMZ) · per-crown CSV · crown polygons (GeoJSON) · STAC item.

Crown detector: Detectree2

  • Open-source tree-crown detector: Mask R-CNN instance segmentation, built on Meta's detectron2.
  • Each tile returns a crown outline and a confidence score.
  • Published weights are used as they are. Nothing is trained here.
  • Weights are mounted read-only at /models and can be picked per project:
WeightsBest for
urban_cambridgeUrban trees, Cambridge UK. Default.
paracouTropical canopy, Paracou UAV.
randresizeRandom-resize full model.
flexiGeneralist: urban and closed canopy.
tropical_closedDense tropical forest only.

The detector only finds crowns. Naming the species is the clustering and labelling work that follows.

Crown embedding: DINOv2

  • Each crown polygon is cut from the full-resolution orthomosaic.
  • A DINOv2 vision transformer returns one embedding per crown.
  • Embeddings are L2-normalised, standardised, then reduced with PCA to 50 components (configurable).
  • The backbone can be picked per run:
BackboneTrade-off
ViT-S/14Fastest, smallest embeddings.
ViT-B/14Balanced. Default.
ViT-L/14Highest quality, slowest.

Clustering and choosing k

  • Look-alike crowns are grouped with KMeans, once for every k in the list. The default list is 2, 4, 6, 8, 10.
  • The elbow, silhouette (higher is better) and Davies-Bouldin (lower is better) scores are computed for every k.
  • The best k is suggested (the red dashed line on the plot), but you can choose any k after reviewing.
  • For review, the app also shows the crowns nearest each group's centre and a t-SNE map of all crowns. Tight, separate patches of colour mean clean groups; mixed colours mean you should try another k.

Naming species

  • Clustering only groups crowns. You supply the species names after reviewing the cropped crowns.
  • The review page shows sample crowns for every group at the chosen k.
  • You type one species per group, and every crown in the group inherits it.
  • Two groups can be given the same species.
  • Labels are stored per run, so an older run can still be finished later.

Outputs

  • Species map (KMZ): opens in Google Earth or any GIS tool.
  • CSV tables: every crown with its species, ready for Excel.
  • Crown polygons (GeoJSON).
  • STAC record: so the dataset can be catalogued and found later.
  • FileBrowser folder: a shareable, read-only link to every file of the run.
  • Every run is kept: compare settings and finish any run later.

Limitations and what they imply

LimitationWhat it means
Detection is not identificationDetectree2 only outlines crowns. A missed or merged crown is a detection problem, not a labelling one.
Species come from youGroups are made by visual similarity. A group is only as accurate as the name you give it after reviewing the sample crowns.
Groups are not always speciesA species can split across several groups, so two groups can share one name. Check the t-SNE map before trusting a k.
Weights are used as publishedNothing is trained here, so pick the weights closest to your forest type.
