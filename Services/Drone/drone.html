Drone

Turn drone imagery into individual tree crowns and species maps.

About this service

Upload one stitched drone photo of your site (a GeoTIFF orthomosaic) and Drone outlines every tree crown it can see. Look-alike crowns are grouped together, you name each group once, and every tree in that group gets the species you typed.

Every run is saved on its own, so you can change the settings and try again whenever you like. Download a species map for Google Earth or any GIS tool, CSV tables with every crown and its species, and a STAC record.

Documentation ↗ GitHub Repository ↗

How to use it

1
Create a project: Sign in with Google, then start a new project for your site.
2
Upload orthomosaics: Add a GeoTIFF (.tif or .tiff) with its coordinates built in, from your computer or a Google Drive link shared as "Anyone with the link". A ground resolution finer than 8 cm per pixel works best, and a project takes up to 10 orthomosaics and 5 GB. If the file has no coordinates, the app asks for the EPSG code.
3
Detect and group: Pick a detector model and settings, then run the analysis. Drone outlines the crowns and groups look-alike ones. The elbow, silhouette and Davies-Bouldin charts suggest how many groups to use, and the t-SNE crown map shows how clean those groups are.
4
Check and tune: Compare the red outlines on the detection overlay with the trees you can see. If results look poor, open the Guide tab, change the suggested setting and run again.
5
Name and export: Type a species for each group, then export the species map (KMZ), CSV tables and STAC record. Every run gets its own read-only folder in FileBrowser.

Methodology

How Drone runs

Detectree2 crown detection · clustering · species labelling · Airflow + STACD

4NameYou type a species for each group

Overview

  • Drone is a Docker app (frontend + backend) behind Nginx at /drone.
  • The backend triggers the compute job; the heavy work does not run in the web page.
  • Everything is saved per run, so you can change settings and run again without losing earlier results.

How a run executes

  1. You sign in with Google, create a project and upload an orthomosaic.
  2. You pick the detector weights and settings and start the run.
  3. The backend triggers an Airflow DAG generated by STACD.
  4. Airflow runs the detection and clustering tasks on the cluster.
  5. The backend polls the DAG until it ends in success or failed.
  6. On success, results are written to data/drone/ and you browse them in FileBrowser.

Crown detector: Detectree2

  • Open-source tree-crown detector: Mask R-CNN instance segmentation, built on Meta's detectron2.
  • Each tile returns a crown outline and a confidence score.
  • Published weights are used as they are. Nothing is trained here.
  • Weights are mounted read-only and can be picked per project:
WeightsBest for
urban_cambridgeUrban trees, Cambridge UK. Default.
paracouTropical canopy, Paracou UAV.
randresizeRandom-resize full model.
flexiGeneralist: urban and closed canopy.
tropical_closedDense tropical forest only.

Preparing the image

  • The detector was trained at one ground resolution, so every survey is first brought to 6.7 cm/px.
  • Scale = native GSD ÷ target, capped at 1.0, so a coarse survey is never upsampled.
  • Native GSD is read from the raster's own geotransform, never assumed.
  • The run log records native GSD, scale and effective GSD for every file.
  • The image is cut into tile_size metre tiles with a buffer overlap.
  • At most 6 crowns per tile are kept; extras are dropped.

From tiles back to one crown map

  1. Project: tile pixel masks become map coordinates.
  2. Stitch: per-tile layers are joined into one, in the orthomosaic's own coordinates.
  3. Confidence filter: crowns under conf_threshold (0.85 by default) are dropped.
  4. Area filter: only crowns between 4 and 2000 m² are kept.
  5. Clean-up: duplicates from the tile overlap are removed at an IoU of 0.9.

Grouping and species labels

  • The detector only finds crowns. Species come from the clustering and labelling that follow.
  • Look-alike crowns are grouped into k clusters, and you get sample pictures of each group.
  • The elbow, silhouette (higher is better) and Davies-Bouldin (lower is better) charts suggest k. The red dashed line is the app's suggestion.
  • The t-SNE map shows each crown as a dot. Tight, separate patches of colour mean clean groups; mixed colours mean you should try another k.
  • You name each group once, and every tree in that group gets that species.

Key settings to tune

SettingDefaultWhen to change it
tile_size10 mBig crowns are missed or cut: raise it.
conf_threshold0.85Far fewer trees than you can see: lower it.
area_max2000 m²A lawn or field is marked as one tree: lower it.
Max crowns per tile6Dense areas look emptier than sparse ones: raise it.
Overlap merge thresholdIoU 0.9One outline covers several trees, or one tree is outlined twice.
Full coverageOffNothing is found along an edge: turn it on.

Example: on one site, the default settings found 19 crowns. With tile_size 20, conf_threshold 0.5 and area_max 200, the same image gave 154 crowns.

Outputs

  • Species map (KMZ): opens in Google Earth or any GIS tool.
  • CSV tables and GeoJSON: every crown with its species.
  • STAC record: so the dataset can be catalogued and found later.
  • FileBrowser folder: a read-only, shareable link to every file of the run. Each run keeps its own folder, so runs never mix.
